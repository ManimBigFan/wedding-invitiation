# Rustic Romance 모바일 청첩장

세 가지 모바일 시안 중 **01 한 장의 편지**를 선택한 현재 버전입니다.

- [01 한 장의 편지](https://manimbigfan.github.io/wedding-invitiation/rustic/?design=letter)
- [02 우리의 한 장면](https://manimbigfan.github.io/wedding-invitiation/rustic/?design=photo)
- [03 여백으로 전하는 마음](https://manimbigfan.github.io/wedding-invitiation/rustic/?design=emboss)

이기훈 · 한승미 / 2027년 3월 28일 오전 11시 30분 / 더채플앳청담. 실제 사진은 `../assets/our-moment.jpg`를 사용합니다.

## 파일

- `index.html`: 표지, 3D 반지 장면과 정적 대체 그림, 초대글, 예식 정보, 갤러리, 달력, 길 안내, 사진·영상 참여 영역과 dialog.
- `styles.css`: 세 디자인의 레이아웃, 종이 질감, 모바일 스타일.
- `script.js`: 시안 선택, 갤러리 확대·색감 전환, 카운트다운, 일정 저장, 복사와 공유.
- `interactions.js`: 자동 봉투 연출 종료, 반지 장면의 스크롤 진행률·문구 전환, 줄 단위 글 등장, 편지 펼침과 사진 정렬. 움직임 줄이기·렌더링 실패 시 정적 표시를 관리합니다.
- `rings.js`: 외부 3D 라이브러리 없이 두 금빛 반지를 그리는 WebGL 렌더러. `interactions.js`보다 먼저 불러옵니다.
- `config.js`: 사진 전송 서비스 주소와 공개 업로드 한도. 비밀 키를 넣지 마세요.
- `guest-upload.js`: 파일 선택·미리보기·진행률·실제 전송·실패 재시도.

1안은 우표가 있는 실제 표지 종이가 봉투에서 올라와 제자리에 놓이는 자동 연출로 시작합니다. 별도 복제 카드를 바꾸어 보여 주지 않습니다. CSS 동작은 1.65초이며, 문서 시작 시점부터 1.9초 이내에 봉투 상태를 해제하므로 느린 로딩이 읽기를 막지 않습니다. 열기·다시 보기·건너뛰기 버튼은 없습니다. 도입 연출 중 스크롤·키보드·터치·포커스 입력이 들어오면 즉시 완료하며, 움직임 줄이기 설정·직접 섹션 링크·뒤로/앞으로 탐색에서는 도입을 생략합니다.

표지와 초대글 사이에는 두 금빛 반지가 크게 회전하며 한 쌍으로 놓이는 3D 장면이 있습니다. 지원 환경에서는 약 240svh(최소 1100px)의 구간 안에서 화면이 잠시 고정되고, 사용자의 일반 세로 스크롤 진행률에 따라 반지의 서로 반대 방향 회전·앞뒤 배치·문구가 변합니다. 휠이나 터치 입력을 가로채지 않으며 반대로 스크롤하면 장면도 되돌아갑니다.

초대글의 종이 접힘과 본문 인화 사진의 기울기가 풀리는 보조 동작도 유지합니다. 제목·초대글·일부 문단은 화면에 들어올 때 줄마다 110ms 간격으로, 각 줄은 0.8초에 걸쳐 한 번 나타납니다. 이름·날짜·조작 버튼은 이 등장 효과로 숨기지 않습니다. 표지 우표는 정적인 장식이고 본문 갤러리의 확대·색감 전환은 유지합니다.

움직임 줄이기 설정에서는 긴 반지 스크롤 구간 없이 정지한 최종 구도와 펼쳐진 본문을 보여 줍니다. WebGL 또는 필요한 CSS 기능을 사용할 수 없거나 렌더링이 실패하면 반지 장면을 정적으로 표시하며, JavaScript가 없을 때도 대체 그림과 본문을 읽을 수 있습니다.

G&S 같은 이니셜·모노그램 장식은 사용하지 않습니다. 봉투는 종이 질감과 접힘선으로 표현하고, 이름이 필요하면 제공된 전체 이름을 유지하세요.

## 최신 인터랙션 참고

사용자는 이전 변화가 작게 느껴진다고 피드백한 뒤 Apple AirPods Pro 3 모바일 페이지의 **「사운드는 과학」** 구간을 담은 7.47초 영상(`2180.mp4`)을 제공했습니다. 추출 프레임에서 확인한, 스크롤에 따라 큰 입체 물체가 회전하고 구도·문구가 함께 바뀌는 흐름을 최신 기준으로 삼습니다. 청첩장에서는 두 금빛 반지가 각자의 방향에서 움직여 한 쌍이 되는 장면으로 응용했습니다. 이 영상은 분석용 참고이며 사이트나 인계 ZIP에 포함하지 않습니다.

김종민의 Form Follows Function을 소개하는 [「구글에서 입사 제의 받은 포트폴리오」](https://www.youtube.com/watch?v=cpEeqACsF_Q)와 [작가의 공식 소개](https://blog.cmiscm.com/?p=3216)는 배경 참고로 유지합니다. 해당 영상은 한국어 자막으로 확인했습니다. 종이·봉투·반지의 형태에 맞는 움직임을 연결하되, 최신 요청의 핵심인 눈에 띄는 3D 장면과 스크롤 전개를 우선합니다.

## 3D 렌더러 연결

`window.WeddingRings.create(canvas)`는 렌더러를 만들며, 사용할 수 없으면 `null`을 반환합니다. 반환 객체의 `render(progress)`에 0~1 진행률을 전달하고, 실패를 알리는 `false` 반환 시 정적 대체 화면으로 전환합니다. `dispose()`는 WebGL 자원을 해제합니다. 반지 형상·재질·조명은 `rings.js`에서 생성하므로 별도 모델 파일이나 외부 3D 의존성이 없습니다.

스크롤 시간과 화면 상태는 `interactions.js`가 관리합니다. 스크롤을 막지 않는 이벤트 리스너와 필요한 프레임만 갱신하는 방식이며, 화면이 정지했을 때 반복 렌더링 루프를 돌리지 않습니다. WebGL 미지원·컨텍스트 손실·움직임 줄이기·2·3안 전환을 수정 후 함께 확인하세요. 실제 기기 성능과 최종 배포 여부는 별도 검증이 필요합니다.

## 사진·영상 보내기

청첩장에서 이름과 파일을 고른 뒤 **올리기**를 누릅니다. 최대 100개, 파일당 80 MiB, 한 번에 총 1 GiB입니다. 각 파일은 서버 저장이 확인된 뒤 완료로 표시됩니다. 실패한 파일은 같은 화면에서 다시 전송할 수 있습니다.

프런트엔드는 GitHub Pages의 정적 파일입니다. 실제 업로드는 별도의 Sites 서버가 D1에 접수 정보를, 비공개 R2에 원본을 저장합니다. 다른 LLM에 전달하는 압축파일의 `upload-service/`에 서버 소스가 포함됩니다.

관리 화면: https://gihun-seungmi-wedding-snap.leegihun42.chatgpt.site/admin

청첩장을 만든 소유자 계정으로 ChatGPT 로그인해야 원본 조회·다운로드·삭제가 가능합니다. 하객에게는 사진 목록이나 원본 주소를 공개하지 않습니다. 서버 환경 변수 `ADMIN_EMAIL`은 관리 계정 확인용이며 서버의 비밀 환경 변수로 설정합니다. GitHub 소스에 넣지 않습니다.

실제 전송은 허용된 GitHub Pages 주소와 서비스 주소에서 사용합니다. ZIP에서 HTML을 직접 열면 디자인은 확인할 수 있지만 브라우저의 출처 정책상 실제 업로드는 라이브 주소에서 확인해야 합니다. 개발 시에는 서버의 허용 출처 목록을 명시적으로 수정하세요.

## 수정 및 배포

정적 파일은 별도 빌드 없이 저장소 `main`에 올리면 GitHub Pages가 배포합니다. 이름·문구·장소는 HTML, 예식 날짜는 `script.js`와 HTML 달력을 함께 변경합니다. 서버 배포는 `upload-service/README.md`를 참고하세요.

확인되지 않은 전화번호·계좌·주차 안내·경품 약속은 넣지 않았습니다. RSVP 수집 기능도 없습니다.
